## 二、启动

**推荐双击 `启动.bat`。** 它会按顺序做完三件事，每一步都有进度提示：

| 步骤 | 做什么 | 就绪标志 |
| --- | --- | --- |
| 1/3 | 拉起语音服务（没在跑才拉） | 9880 通，等待时打点，最长 120 秒 |
| 2/3 | 启动 AstrBot | `Key OK.` + 6199 通，WebUI `http://127.0.0.1:6185` |
| 3/3 | 拉起 QQ + NapCat | NapCat 没在跑才会开；**扫弹出的二维码登录机器人账号** |

顺序很关键：AstrBot 只在启动那一刻把 miyako 权重推给语音服务，反了声音就不是
九条都的。第 3 步只在 NapCat 自己的 6099 端口没人占时才启动新实例，所以你后台
挂着本人 QQ 也不影响——照样会弹窗口给你扫码。NapCat 已经在跑时不会重复开，
只会把它的网页端（http://127.0.0.1:6099）打开。

想自己控制每一步，按这个顺序双击：

| 顺序 | 脚本 | 端口 | 等到什么算好 |
| --- | --- | --- | --- |
| 1 | `tools\start-gsv.bat` | 9880 | `Uvicorn running on http://127.0.0.1:9880`，约 40 秒 |
| 2 | `tools\start-astrbot.bat` | 6185 / 6199 | `AstrBot started.` |
| 3 | `tools\launch-napcat.bat` | 6099 | QQ 登录完，AstrBot 出现 `适配器已连接` |

QQ 已经在跑的话第 3 步可以跳过 —— NapCat 断线会自己重连，所以偶尔刷
`ECONNREFUSED 6199` 是正常的，等几秒就好。

**三个窗口都别关。** 关语音只是变哑，关另外两个就完全不回话。

### 只重启 AstrBot（不动 QQ）

双击 **`tools\start-astrbot.bat`**。NapCat 那边会自动重连，不用重新扫码。

> 什么时候需要重启：改了 `cmd_config.json`、换模型、改了插件、或者群里开始报
> `LLM 响应错误: All chat models failed: APIConnectionError`。
> 这个脚本会先校验 API Key 有没有混入空白字符，看到 `Key OK.` 才算启动。
> 报错的成因和判断方法见「七、两条常见报错」。

**如果启动时报 `Cannot acquire lock file`**，说明已经有一个实例在跑。两种情况：

- 你连点了两次 → 直接关掉报错那个窗口，别管它
- 窗口早关了但进程还在后台（任务栏看不到、也点不掉）→ 双击 **`tools\stop-astrbot.bat`** 结束它，再启动

> 第二种很常见：AstrBot 的控制台窗口被关掉后，Python 进程经常继续跑。
> `tools\stop-astrbot.bat` 是按 6185/6199 端口找进程再结束的，不用开任务管理器。

### 首次登录

1. QQ 窗口弹出后，用**机器人小号**扫码登录（不要用大号，也别和你本人账号混着登）
2. 登录成功后，NapCat 窗口会打印 `NapCat Start`、`[OneBot] ws client connected`
3. AstrBot 窗口会出现 `qq(...) connected` 之类字样 —— 这时链路就通了

> 如果 NapCat 窗口一闪就没了：右键 `tools\launch-napcat.bat` → 以管理员身份运行。
> 还是不行再试 `local\NapCatShell\launcher.bat`（官方脚本，只认注册表）。

### 插话频率怎么定

由 `willingness_gate` 统一管理，不再逐条随机抽样。没人提到她时，等10秒安静间隔后评估；
连续聊天最多积累30秒。提到昵称或@后关注180秒，安静间隔缩到1.5秒、连续批次上限6秒。
冷态多人热聊会缩短批次上限，但提高接话难度，避免把人类聊天热度误当成邀请。

模型先判断 `bot/other/public/unclear`，再决定 `reply/listen`；只有对象合适且分数达到本轮阈值才生成。
它可建议后续阈值，每次最多改1分，限4–9，120秒后回落。实际回复后冷却45秒（冷态）/12秒（关注态）。
模型在生成阶段仍可选择继续旁听。显式@或引用她走原生回复，越过这些主动门控。
这些分数是策略信号，尚无真实群聊准确率；参数及验收方法见[交接文档](AGENT_HANDOFF_2026-10-23.md)。

### 防刷屏

`platform_settings.rate_limit` 统计每个会话的**入站事件**，早于插件与群上下文记录：

```
count: 0      关闭入站丢弃；主动插话另有冷却和调用预算
time: 60      窗口 60 秒
strategy: discard
```

`discard` 超额会丢掉整条入站消息，包括@；`stall`会延迟处理。复现模板关闭这层限流，
已有配置需自行检查，`doctor.py` 会提示。保持平台总白名单，仅接入目标群。

### 人设现在有两个版本

**现行：卡片版**（`persona\九条都-群聊人设.md`，约 1440 字）
- 按角色卡的体裁写：散文描述"她是谁"，配 10 组对话例子，只留 4 条底线规则
- 反馈依据：上一版是 6362 字的规则清单，14 条"不要"，模型被这么多否定指令
  拽得拘谨、客套，群里反映"感觉不对"。卡片版把长度上限从 60 字收到 40 字，
  删掉所有重复规则，重心全放在例子上——**模型抄例子，不抄条目**

**备份：规则版**（`persona\backup\九条都-群聊人设-规则版-2026-10-22.md`）
- 想切回去：把备份复制回 `persona\九条都-群聊人设.md`，跑 `tools\apply-persona.bat`
- 规则版里详细的成人向样本段落也保存在备份里，需要可整段搬回

改卡片版时注意：例子就是她的声音来源，**改例子比加规则有效十倍**。

### 人设为什么这么写

改人设时最容易犯的错，是把它写成"性格形容词清单"——温柔、怕生、天然呆、节俭。模型会把每一条都当成
"每句话都要体现"，结果就是：每句都道歉、每句都结巴、动不动塞设定，反而最不像人。

现在这份是按行为约束写的，几条原则可以复用：

- **给触发条件，不给形容词**。"被夸会慌"要写成"被夸 → 立刻转移话题、找借口走开"。
- **给配额，不给"偶尔"**。"偶尔"= 模型每三条来一次；"十条里最多一条"才收得住。
- **写清什么时候不触发**。她爱吃醋，但普通异性社交照吃醋就变味了，所以要写"只有被故意逗才嘟囔一句"。
- **反模式比正面描述管用**。列一串"不要说'有什么可以帮你的吗'"，比说十遍"你不是助手"有效。
- **给她自己的生活**。有具体的菜、店、番、物价，她才接得住话；只写性格，她只能回"嗯……对不起"。
- **别让她当百科**。专业问题一律"我不太懂，群里有人更懂"，这是最容易被当成助手穿帮的地方。
- **但别让她只会反问**。这是上一条的副作用：约束一多，模型会退化成"那你呢""你觉得呢""我也不太懂"，
  每条都在接话，一整晚下来零信息，比当百科还难受。所以必须再补一条硬要求：
  **每条回复至少带一样东西——一个判断、一段自己的经历、一个具体信息**，否则就是敷衍。
  反问的配额另算：十条里最多三条以问句结尾。
- **也别为了"有话可说"把语气洗掉**。这是上上条的反向副作用。只要求"给判断、给经历"，
  模型会写出一个**开朗、利落、会讲俏皮话的普通女生**——内容有了，但换谁都能说，跟九条都没关系了。
  她的辨识度不在标签，在说话的**形状**：先犹豫（"那个……"）、给意见前先道歉、说完怀疑自己、
  慌起来句子碎掉、心里一直在算钱。这些必须写进"怎么一眼认出是她"，并且在**样例里同时体现语气和内容**。
  样例比规则管用得多——模型抄样例，不抄条目。

一句话检验：**把名字遮住，还能认出这是她吗？** 如果换成任何角色都成立，那就是描述太泛了。
第二句检验：**这条回复里有信息吗？** 如果删掉之后对方什么也没少知道，那就是废话。
第三句检验：**这条回复有她说话的形状吗？** 如果读起来像任何一个人，那就是在写人，不是写她。

### 要不要开思考模式

**默认关闭，建议保持关闭。** 实测数据（deepseek-flash，同一份人设，5 组真实群聊输入）：

| 模式 | 平均延迟 | 推理 token | 回复长度 |
| --- | --- | --- | --- |
| 关闭 | 1.05s | 0 | 23 字 |
| low | 1.52s | 53 | 25 字 |
| high | 1.38s | 42 | 24 字 |

带 40 条群聊上下文（1669 token）时：关闭 1.21s、low 1.50s、high 1.52s。

结论：**延迟只差 0.3 秒，质量提升是噪声级的。** 同一场景重复采样，有时 low 的追问更准
（"是一两天，还是天天这样？"），有时关掉反而更自然；吵架站队、技术问题拒答这些关键行为，
三种模式全都做对。人的"像不像"是 prompt 决定的，不是推理决定的。

还有一个**硬风险**：思考的推理 token 也算进 `max_tokens`。实测 `max_tokens=40` + high，直接返回**空消息**；
`max_tokens=150` 也出现过一次空回复。群聊里冒出一条空白消息很尴尬，而且要排查很久。

真想试的话：双击 `toggle-thinking.bat`，选 2（low）比 3（high）稳，因为 high 更容易把话说得偏解释性。
试完记得切回 1。

### 图片 / 表情包识别

**状态：已开启。** 看图用智谱 GLM-4V-Flash（免费），Key 在 `.env` 的 `ZHIPU_API_KEY`。

DeepSeek 是纯文本模型，看不了图。所以要经过一个「看图模型」把图片转成一句中文描述，
再把描述放进她的上下文——她"看懂"的其实是那句描述。

链路：

```
群里一张表情包
      ↓
caption_filter（本项目的插件）判断要不要看
      ↓  只放行「表情包」和「@ 她的图」
智谱 GLM-4V-Flash（免费）→ "一只猫竖大拇指，得意的表情包"
      ↓
拼进上下文：[Image: 一只猫竖大拇指，得意的表情包]
      ↓
九条都按这个反应
```

**为什么要过滤**：AstrBot 原生是**每条群消息**进入时都做一次图片描述，不管她后面回不回。
群友刷表情包的频率很高，不过滤的话调用量会很吓人。过滤规则：

| 情况 | 是否描述 |
| --- | --- |
| @ 她 / 唤醒她的消息里的图 | ✅ 全部描述 |
| 只发图、没有配文 | ✅ 当作表情包，描述 |
| 图文混排 | ❌ 跳过（除非带 QQ 表情包标记 `sub_type=1`） |
| 纯文字 | ❌ 不涉及 |

### 怎么让她看图（重要）

**@ 她、图、问题要放在同一条消息里发。**

QQ 里正确的操作是：点她的头像/昵称插入真正的 @ → 再贴图 → 打字问"这是谁" → 一次发出。
这样她既有 @ 唤醒，图也在当前消息里，插件会把图片描述直接塞进 prompt。

三种常见错误姿势：

| 做法 | 为什么不行 |
| --- | --- |
| 手动打 `@五条都` 这几个字 | 那是**普通文本**，不是真 @，不会唤醒她。日志里显示成 `@五条都` 而不是 `[At:3820510054]` |
| 先发图，再单独 @ 她 | 图是上一条消息，会进上下文但不在当前 prompt 里，能看见但不一定接得上 |
| 先 @ 她，等她问"你想说什么"，再发图 | AstrBot 的空 @ 等待只接**带文字**的下一条，纯图会被跳过 |

最稳的是第一种。退一步：单独发图也行，她有 50% 概率主动接一句。

### 纯图消息她会不会回

**会，但不是必回。** 这里有个 AstrBot 的坑：纯图消息走的是"主动插话"通道，传给模型的
`prompt` 是 `event.message_str`，纯图时它是**空字符串**——图片只放在 `image_urls` 里，
而 DeepSeek 是纯文本模型，图片会被直接丢掉。结果就是她对着空 prompt 瞎答。

插件把这条补上了：决定对纯图开口时，先把图片描述写进 `message_str`，
模型收到的是 `[群里发了一张图：一只猫竖大拇指，得意的表情包]`。

具体规则：

- 纯图消息：**50% 概率**接一句
- 同一个群两次对图开口至少隔 **60 秒**，防止有人刷图她刷屏
- 同一张图只描述一次（按 URL 缓存），表情包反复出现不重复花钱
- 被 @ 时不受这个概率限制，正常回复

调这两个数就改插件顶部的常量：

```
IMAGE_REPLY_PROBABILITY = 0.5     # 对纯图开口的概率
IMAGE_REPLY_COOLDOWN = 60.0       # 同群冷却（秒）
```

### 她能认出角色吗

**通用视觉模型不认识任何 9-nine- 角色。** 你发一张希亚，模型只会说"黑色中长发的少女"，
不会说"希亚"。这不是配置问题，是模型没这个知识。

能做的是**特征对照表**：把角色的外形写进 `image_caption_prompt`，让模型按特征对号入座。
当前写了四个（来源：萌娘百科 / VNDB / 百度百科交叉核对）：

| 角色 | 对照特征 |
| --- | --- |
| 九条都 | 棕色及腰长发、刘海垂在两眼之间、蓝眼睛、头上别着发饰 |
| 希亚 | 黑色及肩发、红瞳、身材很小、黑色洛丽塔裙配黑连裤袜 |
| 天 | 白色长发、紫瞳、左侧马尾且鬓角有小辫子、常穿橙色露脐连帽衫 |
| 春风 | 浅紫色双马尾长发、青色眼睛、白色制服配深蓝波点发带和彩色花瓣发夹 |

> 春风的发色各家写得不一致（百度百科写"银白色"，VNDB 和 PixAI 都写"浅紫色"），
> 这里取后两者——两张立绘资料一致，可信度更高。

**加角色的方法**：改 `cmd_config.json` 里的 `provider_settings.image_caption_prompt`，
照上面的格式续写 `名字=发色发型、瞳色、服装`，然后重启。提示词约 300 字，
每次识图都会带上，但 `glm-4v-flash` 免费，所以没有成本顾虑。

三条经验：

- **只写一眼能看出来的特征**（发色、发型、标志性服装），别写性格、身高数字这类图上看不出的。
- **把"不吻合就只描述特征，不要硬套"留在提示词里**。否则小模型会把每个动漫少女都认成同一个人。
  实测反例：纯文字表情包"今天不想上班只想躺平"，输出是`不想上班只想躺平的表情包`，没有乱认人。
- **同人图画风差异很大**，能对上就对上，对不上就退化成纯描述，这比认错人好。

> 另外测过：`glm-4v-flash` **能读图上的中文**（表情包配字基本能抄对），这点不用额外配置。
> 但它英文倾向重，提示词里必须写死"必须用中文"，否则会返回英文描述。

想要明显更强的识图，只能换模型。智谱的 `glm-5.3-flash` 支持视觉，但当前账号返回
`1113 余额不足或无可用资源包`，需要充值；其余 `glm-5.x / glm-4.6` 都是纯文本，喂图片
会报 `messages.content.type 参数非法`。

**开启步骤：**

1. 打开 https://bigmodel.cn 注册（手机号即可），实名后到「API Keys」新建一个
2. 把 Key 粘到 `.env` 的 `ZHIPU_API_KEY=` 后面，存盘
3. 双击 **`tools\vision.bat`** → 选 `1`（它会先用这个 Key 实打一次智谱接口，401 会直接拒绝开启，
   不会等你在群里发图才发现问题）
4. 重启 AstrBot

`tools\vision.bat` 选 `2` 可以随时关掉。选 `3` 直接打开 `.env` 改 Key。

> 想换成别家看图模型：改 `cmd_config.json` 里 `provider` 中 `zhipu-vision` 的 `model` 和
> 它对应 `provider_source` 的 `api_base` 就行，只要对方是 OpenAI 兼容接口。

### 看视频

群里发视频时，`@她` 她会看。做法是抽帧：ffmpeg 从视频里抓 3 张（约每 1.5 秒一张），
逐张交给看图模型，合成一句描述放进 prompt。

- **只在 @ 她 / 唤醒她时看**，普通群消息里的视频不抽帧，避免每条都跑三次识图。
- 需要 ffmpeg。脚本会按顺序找：环境变量 `FFMPEG_PATH` → PATH 里的 `ffmpeg` →
  `D:\ImageMagick-7.0.10-Q16\ffmpeg.exe`（你机器上现成的那个，实测可用）。
- 视频描述按文件缓存，同一个视频不会被反复分析。

### 表情包库

插件 `sticker_pack`。她自己攒表情包，也会自己发。

**收谁的不收谁的**：先看人，再看图。每个群友发过几张她都在记账，
**发够 3 张**才开始收这个人的——发得少的人随手一张不占库位，发得多的才是"供货商"。

- **收**：纯图消息，或带 QQ 表情标记 `sub_type=1` 的图，下载存到
  `local/AstrBot/data/plugins/sticker_pack/pool/`，按文件头认出 gif/png/jpg/webp，
  sha1 去重，同一张只存一次。
- **淘汰**：库满 300 张就**随机丢一成**，不管先后。
- **发**：回复之后按 **8%** 概率附一张；有人说到"表情包""来个表情""斗图"时**必发**。
- **不自觉**：回复超过 70 字不附图；同一个群两次自动附图至少隔 25 秒。
- 想清空就直接删 `pool/` 目录和 `index.json`。

`index.json` 里除了图，还记了每个群友发图次数（`senders`），可以打开看看谁是大户。

调参在插件顶部：`STORE_MIN_SENDER`（几个人开始收）/ `MAX_STICKERS` / `EVICT_RATIO` /
`SEND_PROBABILITY` / `MAX_REPLY_LEN` / `MIN_INTERVAL`。

### 联网搜索（已开启）

**用 DeepSeek 自己的搜索接口，不需要任何代理。** 接口是
`https://api.deepseek.com/v1/tools/search`，和你聊天用的是同一个 key、同一个域名，
国内直连。实测 0.5 秒返回，结果里带摘要和来源（百度百科、新闻站等）。

配置（已完成）：

```
provider_settings.web_search            = true
provider_settings.websearch_provider    = "deepseek"
provider_settings.websearch_deepseek_key = ["<你的 DEEPSEEK_API_KEY>"]
provider_settings.web_search_link       = true      # 回复里带来源链接
```

**她不会每条都搜。** 由模型自己判断——"帮我查一下""最近有什么新闻""这个多少钱"
这类才会触发工具调用，普通闲聊不会。工具名是 `web_search_deepseek`，
另有 `deepseek_fetch_web_page` 用来抓整页。

**费用**：搜索按次计费，和聊天 token 分开算。如果发现她搜得太勤，把
`web_search` 改回 `false` 就关掉了，不用动别的。

> 为什么不用 tavily / brave：那两个要外币卡还得能连外网。国内的博查也行（`bocha`），
> 但既然 DeepSeek 的 key 已经在手上，没必要再开一个账号。

### 让她说话（GPT-SoVITS）

**能，而且 AstrBot 原生支持**，适配器叫 `gsv_tts_selfhost`，默认连 `http://127.0.0.1:9880`。
不需要改造机器人，只要有模型 + 起一个 API 服务。

三步：

1. **训练**：用 GPT-SoVITS 官方整合包，准备 5～10 分钟干净人声（无 BGM、无混响）切片，
   训练 SoVITS + GPT 两个权重，导出为 `xxx_e10_s100.pth` 这种。
2. **起服务**：整合包里跑 `api_v2.py`（默认监听 9880）。它会加载权重并暴露 `/tts`。
   先用 `tts_probe.py` 验证能不能出声音。
3. **接进来**：后台 → 语音合成 → 新建提供商 → 类型选 `GPT-SoVITS TTS(本地加载)`，
   API 地址填 `http://127.0.0.1:9880`，填参考音频和参考文本；然后在
   `provider_tts_settings` 里把 `enable` 打开、`provider_id` 指向它。

参数建议：

- `dual_output = true`：文字和语音一起发，不然群里只有语音没法翻记录。
- `trigger_probability` 建议 `0.15`：不是每条都发语音，否则很吵。
- 参考音频选**情绪平稳、语速偏慢**的一段，她的语气是软而慢的。

**关于音色**：GPT-SoVITS 学的是音色和韵律，不学"她怎么说话"。台词风格还是靠人设控制，
所以先把文字调顺，再考虑配音——反过来会很痛苦。

### 训练集筛选（训练前用）

`tools\voice-screener.bat`：扫一个文件夹，把明显不能用的挑出来。**只看声学指标，离线、不花钱、几秒跑完。**

双击后把文件夹拖到窗口里（或直接拖到 .bat 上），它会逐个文件打分：

```
OK   100分   6.0s SNR  47 静音 39% 峰值 -8.0dB  01_干净人声.wav
删    25分   6.0s SNR   9 静音  0% 峰值 -5.7dB  底噪太高 SNR 9dB（可能有音乐）02_人声加音乐.wav
看    65分  20.0s SNR  47 静音 41% 峰值 -8.0dB  太长 20s（该先切片）   07_太长.wav
```

判据：

| 指标 | 意义 |
| --- | --- |
| **SNR** | 说话段和停顿段的能量差。差值小 = 停顿里一直有东西 = 背景音乐或空调声。**这条最有用** |
| 削波 | 峰值贴顶，声音是破的，训练出来会有杂音 |
| 静音占比 | 几乎没停顿（像连续音）或几乎没声音，都不适合 |
| 频谱平坦度 | 接近噪声 |
| 时长 / 采样率 / 声道 | 太短没上下文，太长该先切片，低于 16k 会糊 |

跑完会在目录下生成 `report.csv`，问你要不要分拣。选 `y` 就移动到
`_keep/ _check/ _reject/` 三个子目录——**只移动，不删任何东西**。

> 这是启发式的，不是人耳。`_check` 那档建议抽听 5~10 条；`_reject` 里如果听到人声
> 正常的，多半是 SNR 阈值太严，改 `voice_screener.py` 顶部的 `SNR_REJECT` 再跑一遍。

推荐流程：**切片 → 筛选 → 人工抽听 → ASR 打标 → 训练**。先筛能省下大量打标时间，
尤其是从视频里扒的素材，背景音乐是最常见的问题。

能不能合成出一段测试音频，输出到 `tts-test.wav`。

### 语音情绪

同一段参考音频会把语气复制到每一句上，所以她原来不管说什么都是同一个调。

现在按**回复内容的关键词**换参考音频，并微调语速：

| 情绪 | 触发词 | 语速 |
| --- | --- | --- |
| happy | 哈哈、笑、太好了、开心、嘿嘿 | 1.05 |
| shy | 对不起、不好意思、抱歉、害羞、脸红、唔 | 0.93 |
| sad | 难过、累、唉、算了、孤单、想哭 | 0.88 |
| normal | 其余 | 1.0 |

四段参考音频都是从她自己 682 条训练集里挑的原声（不是另外录的）。

**说实话的预期**：换参考音频主要改变语速、力度、气口，**音高几乎不变**
（同一个人，实测中位 F0 都在 280Hz 左右）。所以别期待"哭腔/爆笑"那种跨度，
它更像是"同一句话说得快一点、轻一点"。

没有对应情绪文件就自动退回 `normal`，不会报错。

参考音频是从训练集里用 `voice-screener` 挑的：5.6 秒、SNR 74、语气平稳礼貌。

**当前是 `both` 模式：每条回复都是「日语语音 + 中文文字」一起发。**

四种模式（`tools\tts.bat` 选 5，或 `tts_setup.py mode voice|half|both|rare`）：

| 模式 | 行为 | 适合 |
| --- | --- | --- |
| `voice` | 每条都是语音，没有文字 | 就是要"她在说话"的效果 |
| `half` | 一半「语音+文字」、一半纯文字 | 有变化不腻 |
| `both` | 语音 + 文字一起发 | **当前**，能听也能读，翻记录方便 |
| `rare` | 约 1/7 的回复带语音 | 偶尔开口，平时文字 |

对应两个参数：`trigger_probability`（触发概率）和 `dual_output`（是否同时发文字）。
`both` = 1.0 + 发文字。

> 每条都合成的两个代价：群里消息量翻倍，而且每条要等 TTS 合成（首句约 5 秒，
> 之后 1~3 秒），所以她会比纯文字模式慢一点。
> TTS 失败会自动退回文字，不会哑掉。

### 设定速查（减少 OOC）

人设已经 6000 多字，再往里塞设定只会稀释指令。所以设定单独放一张卡：

`persona\九条都-设定速查.md`——作品信息、能力机制、人物关系、剧情要点，
外加一节"容易被写错的地方"（女路人是玩家爱称、能力不是念力、她不是天然呆）。

插件 `knowledge_card` 只在聊天**命中关键词**时把这张卡临时塞进这一轮的上下文
（设定 / 剧情 / 原作 / 能力 / 圣遗物 / 魔眼 / 希亚 / 春风 / 新海 …… 共 20 个）。
平时完全不占 token，也不花钱。

> 为什么不用 AstrBot 的知识库：它需要配 embedding 模型（DeepSeek 没有，得用智谱的
> `embedding-3`），还要建库、切片、绑会话。她的设定总共一千字不到，一张卡片
> 比向量检索更直接。真要上知识库，`persona` 里的文件也能直接导入。

**改设定**：直接编辑那个 md，插件会按文件修改时间自动重载，不用重启。

### 启动顺序（重要）

**先 `tools\start-gsv.bat`，等它加载完，再 `tools\start-astrbot.bat`。**

AstrBot 在启动时就会去连 9880 并推送权重，如果那时 GSV 还没起来，
TTS 初始化会失败，语音就不能用——得重启 AstrBot 才好。GSV 本身加载约 40 秒。

`tools\start-gsv.bat` 会拉起 `F:\GPT-SoVITS-v2pro-20250604\runtime\python.exe api_v2.py -p 9880`。
关了那个窗口语音就停，但文字聊天不受影响。

### 语言：文字中文，语音日语

**群里看到的是中文，听到的是日语。** 这是两个独立的层：

```
模型回复（中文） ──┬─→ 直接发出去            ← 文字，中文
                  └─→ 翻成日语 → TTS 合成    ← 语音，日语
```

为什么这么做：参考音频是日语原声，日语对日语合成几乎没有损失；直接拿中文喂给日语模型，
发音会怪。而群里又需要中文文字才看得懂。

实现在插件 `miyako_tts`：用 AstrBot 官方接口注册了一个自己的 TTS Provider
（类型 `miyako_gsv_tts`，继承内置 GSV 源），**合成前先把文本翻成日语口语**，
其它一概不动。旧版 `tts_translate`（monkey-patch 内核）已停用，备份在
`data\plugins_disabled\`。

- 已经是日语的文本直接跳过，不重复翻
- 翻译结果按原文哈希缓存，同一句不翻两次
- 翻译失败就退回原文合成（宁可怪一点，也不能没声音）
- 翻译走的是你配置的聊天模型（DeepSeek），每次约多 0.6~1 秒

翻译提示词在 `miyako_tts/main.py` 顶部的 `TRANSLATE_PROMPT`，要求"年轻女性口语、
语气软、不要过度敬语"。如果觉得翻得太生硬，改那里。

### 换模型 / 手动接线

**文件全部放项目里的 `voice/` 目录**，不用写到别处：

```
qq-bot\voice\
  weights\
    xxx_e10_s100.pth     <- SoVITS 权重
    xxx-e15.ckpt         <- GPT 权重
  ref\
    miyako_ref.wav       <- 参考音频，3~10 秒，干净无 BGM
    prompt.txt           <- 可选，写这段音频里说的原话
```

文件名不用改，脚本按后缀认：`.pth` 当 SoVITS，`.ckpt` 当 GPT。同一种有多个时取**最新的**并会提示。

放好之后：把 `api_v2.py` 跑起来 → 双击 **`tools\tts.bat`** 选 `2`（自动扫 `voice/`）→ 重启 AstrBot。

脚本会先检查三个文件都在、9880 通不通，然后写进 `cmd_config.json`：

- `provider_sources` 加一条 `type: gsv_tts_selfhost`（AstrBot 启动时会把权重路径
  POST 给 `/set_sovits_weights` 和 `/set_gpt_weights`，所以不用手动在 GSV 里选）
- `provider` 加一条 `gsv-miyako`
- `provider_tts_settings`：`enable=true`、`provider_id=gsv-miyako`、
  `dual_output=true`（文字+语音都发）、`trigger_probability=0.15`

`tools\tts.bat` 选 `1` 看状态（会列出 voice/ 下扫到的文件和 9880 通不通），
选 `3` 关掉，选 `4` 手动填路径（不想放 voice/ 时用）。

> 语速建议先用 `tts_setup.py on --speed 0.9`，她的语气是慢的。
> 参考音频挑情绪平稳的一段，别用笑场或拖尾音的，否则每句话都会带那个味道。

### 一键体检

双击 **`tools\doctor.bat`**，一次查完这些：

```
✓/!/✗  DeepSeek Key / 智谱 Key
✓/!/✗  6185、6199、6099 三个端口
✓/!/✗  Safe Mode、图片描述、视觉 provider、管理员 QQ、限流策略、关键词过滤
✓/!/✗  人设文件与数据库是否一致（改了没 apply 会在这里报出来）
✓/!/✗  两个插件在不在、表情包攒了多少张
✓/!/✗  ffmpeg
✓/!/✗  语音是否接线
```

`✗` 是会导致不工作的硬故障，`!` 多半是"没启动"或"没配置"。
改完东西重启前后各跑一次，比翻日志快。

## 六、费用

费用取决于主对话、意图判断、画像提炼、摘要、视觉与兜底翻译的总调用量，
以及当期模型单价、缓存命中和输出长度；不能仅凭人设长度估算月费。

意图请求最多每群每分钟6次，消息先合批；`SCORE_PROVIDER_ID` 可单独选择模型。
画像与摘要可通过 `MEMORY_PROVIDER_ID` 使用另一个模型，默认均沿用会话模型。
画像注入上限800字符，摘要上限600字符；不发送语音的轮次不再要求生成日语台词。
`mark_as_temp()` 只是不写持久历史，仍计入当次输入token。

查看插件data目录的 `willingness_gate/decisions.jsonl` 和 `memory_distill/calls.jsonl`，
可得到对应调用的实际usage，供应商未返回时记null。完整费用还应结合框架主调用记录和供应商账单。

## 七、两条常见报错

### 1. `LLM 响应错误: All chat models failed: APIConnectionError: Connection error.`

群里发消息，机器人回一句这个。字面意思是"连接错误"，但**八成跟网络无关**。

**这个报错的真正含义是"请求根本没发出去"。** openai SDK 把所有传输层异常都统一包装成
`APIConnectionError: Connection error.`，其中就包括 `LocalProtocolError`（请求头非法）。
最容易踩的是 **API Key 里混进了尾随空格或换行** —— 那行请求头不符合 HTTP 规范，
在 h11 编码阶段就被拦下，一个字节都没发到 DeepSeek，于是报"连接错误"。

判断依据（照这三点看，一眼就能区分）：

| 特征 | Key 脏了 | 真·网络问题 |
| --- | --- | --- |
| 每次重试耗时 | 固定 ~1 秒，很快就失败 | 5–12 秒不等，像在等超时 |
| `check-llm.bat` | **全部通过** | 会卡在 DNS / TCP / TLS 某一步 |
| 换机器 / 换网络 | 没用，照样报错 | 换个网络就好 |

**处理：**

1. 双击 **`tools\start-astrbot.bat`**。新版本会先自检 Key，发现空白字符会直接提示并打开 `.env`，
   不会再把脏 Key 悄悄塞进去了。看到 `Key OK.` 才算过。
2. 如果它提示 `still contains whitespace`：打开 `.env`，**把 `DEEPSEEK_API_KEY=` 整行删掉重打一遍**，
   别在行尾留空格，存盘后再启动。
3. 自检（`check-llm.bat`）里真的卡在 DNS/TCP/TLS 了，才按下面的分支走：
   - 直连失败、提示"改走代理" → 后台把 provider 的 `proxy` 填 `http://127.0.0.1:7892`（Clash 要开着）
   - 报 401 → Key 失效；报 402 → 余额不足；报 404 → 模型名或 api_base 不对

> 这个坑的根源在批处理：`set VAR=值 && 程序` 这种写法，`值` 后面会**自动多一个空格**。
> 现在两个启动脚本都改成了在脚本层 `set "DEEPSEEK_API_KEY=..."` 再让子窗口继承，
> 并且读取时会自动裁掉尾部空格。

> 另外：不要从带代理变量的终端里启动。`tools\start-local.bat` / `tools\start-astrbot.bat` 已经加了清空
> `http_proxy` / `https_proxy` 的处理，正常双击不受影响。

### 2. `UpdateServiceError: Failed to parse release information.`

**这条可以完全忽略。** 它只是"检查更新"这个功能在用，跟你聊天没半点关系。

原因是 `github.com` 在你这网络上直连不通（实测 `api.github.com` 通、`github.com` 超时），
AstrBot 拿不到 release 页面就解析失败。日志里官方自己也写了「不影响除项目更新外的正常使用」。

想升级别点后台那个按钮，直接用命令：

```bat
cd local\AstrBot
..\venv\Scripts\python.exe -m pip install -U astrbot
```

## 八、常见问题

| 现象 | 原因 / 处理 |
| --- | --- |
| `start-local 提示 QQ not found` | QQ 不在 `E:\QQ.exe` / `E:\QQ\QQ.exe` / Program Files，改 `tools\start-local.bat` 里的探测路径 |
| NapCat 窗口闪退 | 先试管理员运行 `tools\launch-napcat.bat`；再不行跑 `local\onekey\NapCatInstaller.exe`（会装配套 QQ+NapCat） |
| QQ 提示版本更新 | **别更新**。NapCat 只认兼容表里的版本，跳版本大概率炸 |
| AstrBot 起来了但群里没反应 | 看 AstrBot 窗口有没有 `connected`；没有就是 NapCat 那边没连上，去 6099 后台看 `websocketClients` 是否启用 |
| 回复很慢 / 带一堆思考过程 | `custom_extra_body` 被清掉了，重新加 `{"thinking":{"type":"disabled"}}` |
| 后台登录报密码错 | `.env` 不设置此密码；新部署看初始启动日志，已设密码在后台修改。旧模板`change_me`+空hash可停服后用`setup_repro.py`备份修复 |
| 端口被占 | 改 `.env` 的 `ASTRBOT_WS_PORT` / `ASTRBOT_PORT` / `NAPCAT_WEBUI_PORT`，同时改 `onebot11.json` 里的 `url` 和 `cmd_config.json` 里的对应端口 |
