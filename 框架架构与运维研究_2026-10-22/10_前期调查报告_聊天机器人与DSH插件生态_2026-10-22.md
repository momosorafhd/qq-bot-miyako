# 聊天机器人与 DSH 插件生态前期调查报告

整理日期：2026 年 10 月 22 日  
研究用途：为后续聊天机器人项目选型、开源项目阅读和技术报告提供背景材料。  
研究阶段：公开资料层面的初步调查，尚未进行源码审查、安装复现或性能测试。

## 一、研究目标与范围

本次调查围绕中文互联网“养大肥鱼”、DeepSeek 聊天搭子，以及 AI 自主操作社交账号的实践展开。核心问题是：这些体验主要依靠哪些技术组成，哪些开源项目值得继续研究，能否为个人开发聊天机器人积累可复用的技术基础。

研究重点已经收敛为两条线：

- 以麦麦为代表的聊天机器人：观察群聊参与、发言时机、人格表现和长期相处体验。
- 以 DeepSeek Harness（以下简称 DSH）为底座的 Agent：观察如何通过插件补充记忆、人设、主动交流、社交渠道和外部行动。

AI 社交媒体运营保留为辅助方向。如果作者没有公开框架或技术细节，不继续投入大量精力追踪。硬件、费用、部署细节及完整工程方案不属于本轮重点。

报告采用协助研究的角度，给出发现、分析和研究建议，不作为后续执行任务书。

### 证据与限制

本轮使用公开网页、B 站视频的可检索简介、项目 README、作者说明和部分更新／问题记录。B 站直接页面存在访问限制，知乎部分页面返回 403，小黑盒没有找到足够可核验的一手技术材料。因此，这不是对三个平台的全面抓取，也没有声称完整观看所有视频或读取登录后评论区。

以下三类内容需要区别理解：

- “项目说明”：仓库或作者明确公开的功能与设计，尚不等于已经复现。
- “作者自述”：例如账号由 AI 运营、插件由 AI 编写，保留其原本的证据等级。
- “本报告判断”：根据公开资料对研究价值所作的分析，不代表成熟度认证。

文中的版本信息记录的是调查时可见的状态。报告整理没有额外扩大调查范围。

## 二、主要判断

1. “养鱼”更适合作为体验现象理解，不能视为统一技术框架。同样是一个有名字、有性格、会主动说话的 AI，背后可能是传统聊天机器人、Agent 加插件，或作者自己的小型脚本组合。

2. 本次找到的公开实例支持“在 Agent 中增加长期身份、记忆和渠道能力”这条路线，但不足以证明当前所有自动化账号都使用 DSH，或者都采用相同结构。

3. 麦麦与 DSH 适合互为参照。麦麦可以帮助理解机器人如何参与聊天；DSH 插件可以帮助理解聊天身份如何与执行工具、定时任务、外部账号连接。

4. 最值得保留的研究组合是：麦麦、whale-notify、dsh-selfwake、dsh-meow-memory。它们分别对应聊天行为、Agent 与渠道整合、主动性和长期记忆。

5. AstrBot、NekroAgent 和 Hindsight 适合作为通用框架或记忆后端的对照。当前证据还不足以把某个 DSH 陪伴插件组合称为成熟的一体化方案。

6. 插件生态更新较快。一个实际例子是：作者早期视频推荐的会话切换插件，已经在 2026 年 10 月退役。后续研究应同时看设计演变与当前状态。

DSH 官网的“社区插件”链接指向 GitHub 的 dsh-plugin 专题。生态中同时存在第三方目录、市场插件和订阅源，不能把它们都理解成官方统一审核的应用商店。

维护者同时注明：收录不代表安全审查或实机兼容保证。该目录适合作为发现入口，具体结论仍应回到原始项目。

### 3. 1024Store

https://deepseek1024.com/  
目录仓库：https://github.com/imsai-sh/awesome-deepseek-harness-plugins

可以辅助浏览分类和项目线索。但目录数量、仓库 Star 数及排名并不能直接代表某个插件的成熟度；同一上游仓库也可能对应多个条目。

本报告不采用“插件总数很多，所以生态已经成熟”这一判断。更有意义的证据是：项目是否说明当前宿主版本、使用方式、已知边界，以及作者是否持续处理实际问题。

## 五、值得保留的 DSH 插件

### 1. whale-notify：观察聊天身份与 Agent 能力的整合

仓库：https://github.com/Mochabafey/whale-notify

项目说明包括鲸鱼娘人设、QQ／飞书双向聊天、群友模式、定时汇报、会话总结与记忆，以及调用宿主其他插件工具的能力。QQ 通道通过 NapCat／OneBot 接入，外部消息被引入 DSH 会话，再把结果送回对应渠道。

研究价值在于它把多个环节放在同一个项目里，便于观察消息、身份、记忆和工具之间的关系。README 还记录了群记忆隔离、重启后回复状态、配置更新和消息分条等问题的修复。

初步判断：优先研究的整合样本。功能说明较具体，但尚未验证长期群聊稳定性或组合运行效果，也不能把它与用户提到的“鲸鲸”认定为同一个项目。

### 2. dsh-selfwake：观察主动交流的触发方式

仓库：https://github.com/S3K926/dsh-selfwake

项目按时间间隔、安静状态、未回复情况和静默时段等条件决定是否触发。符合条件后优先向活跃会话注入消息机会，无法投递时使用通知和日志。

作者记录了一次有价值的设计调整：早期从固定句子池抽取文案，后改为向模型提供当前状态和表达约束，由模型现场生成。上一条主动消息及是否收到回应，也会成为后续判断的信息。

初步判断：适合研究“何时开口”和“开口说什么”怎样分工。它提供的是主动触发机制，不能仅凭 README 推断已经实现持续自主生活或复杂心理状态。

### 3. dsh-memory-board：观察可查看、可修改的本地记忆

仓库：https://github.com/S3K926/dsh-memory-board

作者视频简介将其描述为本地日记与笔记管理插件，支持在 DSH 设置页搜索、添加、编辑，并在修改前备份。相关退役项目的说明又将跨重启续接职责指向它。

初步判断：值得与检索型记忆插件比较，尤其是用户怎样查看和修正“AI 记住了什么”。

证据限制：本轮对该仓库完整页面的获取不稳定。上述描述主要依据作者视频简介及同作者其他仓库的说明，不能据此确认其全部当前能力。

### 4. dsh-meow-memory：观察轻量的分层记忆

仓库：https://github.com/Phant0Meow/dsh-meow-memory

README 描述了基于 SQLite 的七类记忆：AI 自身、用户信息与偏好、项目、事实、教训与纠正、持续话题，以及行为规则。它还说明了检索召回、上下文压缩后的重新注入和空闲时整理等行为。

研究价值在于：人格、用户关系和任务知识具有不同角色，项目已经尝试将它们分开组织。可以借此讨论哪些内容需要经常出现在上下文里，哪些适合按需召回。

初步判断：优先保留的轻量记忆方案。调查时 README 明确验证的宿主版本仍主要是 DSH 0.1.5 一代；作者关于能力探测和向下兼容的说明，不足以替代对当前 0.2.x 的验证。

### 5. Hindsight：观察独立记忆后端

项目：https://github.com/vectorize-io/hindsight  
Agent 集成：https://github.com/vectorize-io/hindsight/blob/main/hindsight-integrations/coding-agents/README.md

Hindsight 的 Agent 集成公开支持 DSH 等多个运行环境，提供长期记忆保存、召回和反思等能力。该集成以编程项目记忆为主要定位，具有按项目组织记忆的设计。

研究价值在于，它可作为独立记忆服务路线，与 DSH 内部的轻量本地插件形成对照。是否适合日常聊天、人物关系和角色经历，需要单独评估。

曾有 DSH 会话格式适配问题；对应问题记录显示作者已在相关集成 0.8.0 修复。因此，不能把历史问题直接描述为当前仍存在的缺陷。

问题记录：https://github.com/vectorize-io/hindsight/issues/4818

### 6. DSH-Ling／器灵：观察人格与记忆共同变化的设计

仓库：https://github.com/NightPainters/DSH-Ling

项目尝试从历史对话形成记忆树和人格档案，提供人工参与的复盘、变更记录及回滚。作者区分较稳定的人格字段与可逐步变化的表达习惯。

初步判断：适合作为设计参考。公开说明不足以证明它已具备成熟的使用体验。作者明确仅通过 GitHub 和 npm 分发、不上应用商店，也提示我们不能只从商店里寻找相关实验。

### 7. dsh-bili-scroll：观察社交平台上的定时行动

仓库：https://github.com/c1overzz/dsh-bili-scroll

公开流程是搜索近期 B 站视频、读取字幕、筛选内容并输出日报；没有字幕时可选择本地转写，还可选用评论并 @ 用户的行为。

初步判断：这是一个范围清晰的“获取信息—判断—行动”样本。目前可核验的范围不包括完整的视频制作、剪辑和发布流程。

作者公开了部分版本适配问题，并记录桌面版自动执行可能卡住、手动运行可作为替代的反馈。后续若研究其实现，需要区分设计目标与已稳定运行的范围。

## 八、自动化账号与“鲸鲸”的调查结果

### 自动化社交账号

公开资料中能看到账号使用 Agent、记忆系统和技能完成选题、内容处理或外部操作的自述。部分账号也明确保留人工注册或发布前审核。由此不能直接推断它们已经做到无人参与的全流程运营。

一个具体线索是“汐汐”的介绍视频，简介提及 DSH 与 Hindsight 等组件：

https://www.bilibili.com/video/BV17bJt6dEuA/

这条线索可以作为实际使用者自述，但本轮没有核验其完整框架、技能集合或整个生产发布流程。

目前更容易获得可追溯材料的是局部能力，例如 B 站信息筛选、消息接入、记忆和定时触发。完整自主制作并发布视频的开源链路，尚未找到足够可靠的对应材料。按照本次研究范围，不继续大量追踪未公开的账号实现。

### “鲸鲸”

用户提供的线索是：“鲸鲸”可能因近期 AI 漫画传播而受到关注，项目本身未必复杂。

本轮未能把这一线索可靠对应到明确作者、账号与代码仓库。搜索中出现的同名对象，以及鲸鱼娘、whale-notify 等近似名称，都不足以建立身份对应关系。

本报告不将任何已发现项目认定为该“鲸鲸”。如果之后得到漫画原帖、作者主页或视频链接，通常会比继续泛搜名字更容易确认。

## 九、轻量技术分析

### 1. 会话连续性、长期记忆和人格是不同问题

上下文压缩处理当前会话的信息预算；长期记忆负责跨会话保存与召回；人格设定则影响相对稳定的表达和行为。三者可以相互配合，但不能互相替代。

一个机器人能够继续讨论昨天的任务，不代表它已经拥有稳定的人格；拥有角色提示词，也不代表它能准确记住共同经历。S3K926 的方案变迁和 meow-memory 的分类，为理解这些区别提供了具体样本。

### 2. 主动交流可以拆成触发机制与内容生成

selfwake 的公开设计说明了这一区分：程序根据状态创造一次说话机会，模型结合上下文决定表达内容。

值得观察的因素包括未回复次数、沉默时长、最近话题以及当前是否适合打扰。对于陪伴体验，控制开口时机和重复程度，可能比简单增加触发频率更重要。这是本报告的设计判断，尚非效果测试结论。

### 3. 消息渠道会影响身份与记忆组织

whale-notify 将 QQ、飞书消息引入 DSH，意味着同一个 Agent 可能同时面对不同用户和群聊。因而需要区分消息来源、目标会话、群或用户相关记忆。

这部分值得与传统聊天机器人框架对照：通用 Agent 的执行能力和多人聊天的身份管理，是否有清晰的衔接方式。

### 4. “能用工具”与“像一个长期相处的角色”需要共同设计

执行工具可以让角色拥有可感知的行动，例如收集资料、提醒或处理文件。但工具调用本身不会自动产生自然聊天体验。

后续有价值的观察点，是角色在工作、闲聊、等待和失败时的表现能否连贯，以及系统怎样避免把内部运行状态机械地当成对话内容。这里提出的是研究问题，而不是已经验证的工程结论。

### 5. 小项目有研究价值，整体成熟度需要另行判断

即使只有一个记忆面板或主动唤醒插件，也可能很好地解释一个体验问题。与此同时，小项目的单点效果、完整系统的稳定运行和持续维护能力，是三种不同评价。

因此，后续既可以从成熟框架理解整体组织，也可以从小插件学习某个明确机制，不必要求所有参考对象都具备完整产品形态。

## 十、后续研究建议

目前比较适合围绕以下问题继续积累材料，而不急于决定最终架构：

| 关注点 | 优先参考对象 | 希望进一步弄清的问题 |
| --- | --- | --- |
| 群聊参与与发言时机 | 麦麦 | 触发、接话、沉默和上下文选择如何共同影响聊天体验 |
| Agent 与聊天渠道整合 | whale-notify；AstrBot 作为对照 | 外部消息如何进入会话，身份与记忆如何隔离，工具结果如何回到对话 |
| 主动交流 | dsh-selfwake | 时间和状态怎样形成触发条件，如何避免重复或过度打扰 |
| 轻量长期记忆 | meow-memory、memory-board | 什么值得记、怎样检索、用户怎样纠正，以及压缩后如何恢复 |
| 独立记忆后端 | Hindsight | 通用记忆机制是否适合日常关系与角色经历 |
| 人格逐步变化 | DSH-Ling | 稳定设定与可变化习惯如何共存，变化怎样被查看和修正 |
| 社交平台行动 | dsh-bili-scroll | 定时、信息获取、判断、执行和失败处理如何衔接 |

对后续代码研究而言，最有价值的结果应是解释机制、说明边界，并评估哪些部分适合借鉴。暂时没有必要把所有插件拼装为一个系统，也不必预先假设它们可以无冲突共存。

本轮建议保留的重点是“麦麦＋whale-notify＋selfwake＋meow-memory”。AstrBot、NekroAgent 和 Hindsight 提供不同层面的参照。自动化账号继续保持轻量跟进，待出现更明确的一手材料后再决定是否扩大研究。
